## What Works
<!-- approaches and solutions that worked here -->
- 2026-10-25 — Postgres FK ON DELETE SET NULL without an index on the referencing column runs one sequential scan of the child table PER deleted parent row: the workspace reset of 100k agent_runs spent 14.2 s of 36 s in the ci_runs.agent_run_id trigger (5k ci_runs), 0.8 s with ci_runs_agent_run_idx (migration 0004; reset 37–49 s → 23–25 s, S19 explain-reset.out) → before a mass delete, index every FK column that points at the deleted table (check 0001 for SET NULL / CASCADE FKs without an index)
- 2026-10-25 — spend/adapters/postgres MonthSpend (Settings A AC23, 2,000 pr_brief docs in TOAST): each jsonb operator on a toasted column detoasts it again, so a CASE with ~8 json-> calls per brief cost 165 ms; one detoast through LATERAL (SELECT b.json || '{}' AS j OFFSET 0) cut it to 35-60 ms; summing inside each UNION ALL branch saves another ~25 ms at 150k rows; an expression index on json->>k gives no index-only scan, and text→timestamptz isn't IMMUTABLE, so it can't be indexed → detoast once per row, aggregate per branch, cover with (workspace_id, time) INCLUDE (cost) indexes (migration 0003)
- 2026-10-24 — leaderboard/adapters/postgres qFindingStats (AC12, NFR1 ~104k findings): one statement over all repos took 520 ms because it spills at the default 4 MB work_mem; splitting the repos into 4 parallel shards gives 150-190 ms each, 6 shards gain nothing on 8 cores, and what's left is ~4 µs of Postgres CPU per finding (30d/all p95 532 ms, down from 5.7 s) → shard by repo before trying indexes (covering and partial indexes measured no end-to-end gain); going below ~500 ms needs a data-model change
- 2026-10-23 — cmd/server component tests of the PR poller (leaderboard_wiring_test.go TestPoll_StartsWhenEnabled): pre-insert a repo 'o/r' into pgtest.Migrated, start with noSeed and PRPollEnabled set in spec.config — the shared GitHub stub serves any owner except acme/ and the poller's first round runs at start, so no tick or sleep is needed; a GET /leaderboard test that must be empty sets spec.now years after the seed instead of skipping the seed, because without the seeded workspace + user rows the tenancy resolver returns 500 → copy this setup for poller/leaderboard component tests

## What Doesn't Work
<!-- dead ends and anti-patterns — the most valuable section -->
- 2026-10-23 — eval overview read one SELECT * from eval_suite_runs per agent: N+1 plus detoasting the large config/case_ids jsonb cost ~450 ms p95 at 50 agents × 40 runs → one ROW_NUMBER() OVER (PARTITION BY agent_id) query that ranks narrow (id, rn) rows, joins back and selects only the DTO columns (jsonb_build_object for config.model): 260 → 23 ms DB time (evals/adapters/postgres FinishedRunsByAgent). Without a pool cap the 50-run burst also hit Postgres 'too many clients' (53300).
- 2026-10-23 — Go net/http on a signed-URL download: a Location with userinfo makes Go send Basic auth, a followed redirect resends Authorization, and *url.Error text embeds the full signed URL → storage leg on its own client copy (no redirects, Jar nil, no auth headers), refuse userinfo/non-https Locations, unwrap *url.Error to .Err before any message (platform/github artifact.go)
- 2026-10-23 — repointel/app blast degraded scan: a cap that counts distinct (name, file) symbols does not bound a per-file index that grows with lines — one name declared on every line kept ~117k entries per 2 MB changed file (480 MiB per scan, security r2 N1) → recompute the changed file's enclosing index when the caller scan hits it, keep nothing per file (TestBlastRadius_ScanRetainsNoChangedFileIndex)
- 2026-10-23 — a per-file cache in a one-pass clone scan keeps every file's full text alive because symbol names/labels are substrings of it (degraded blast scan: 845 MiB live heap) → keep per-file state only while scanning that file, strings.Clone what is stored, share identical scans and cap concurrent scans (repointel/app/blast.go, blast_load_test.go)
- 2026-10-22 — a 1,024-slot chan per SSE subscriber costs ~105 KB each (2,000 streams = 213 MB) → runbus uses a growing slice queue + 1-slot wake channel + pump goroutine (≈3.5 KB idle); callers must drain C() or Close (platform/runbus state.go)
- 2026-10-22 — per-name ReferenceLines over a hostile clone file is O(names × size) between ctx checks (1,000 names × 2 MB: 31–89 s, cancel ignored) → one Aho-Corasick pass per file with a ctx tick every ~32K units of work, plus a binary-search enclosing-symbol index (repointel/domain/refscan.go; differential test vs ReferenceLines)
- 2026-10-22 — a panic on a pool worker goroutine (reviewer/app mapOrdered → LLM port/provider adapter) bypasses the run's recover and kills the whole server → workers recover, stop the pool and re-raise on the caller after wg.Wait (pool.go; TestRun_APanicInAProviderFailsOnlyThatRun); same rule for project-context reader goroutines (readRunDocSafely)
- 2026-10-22 — a CTE + self-join UPDATE over rows bulk-inserted earlier in the same transaction (repointel ResolveReferences): the planner has no statistics for them and re-ran a HashAggregate per row — 67 s for 138k references on a 5,000-file repo (AC3066 failed at 92 s) → one GROUP BY … HAVING count(DISTINCT …)=1 subquery (≈1 s); don't ANALYZE inside the tx (SHARE UPDATE EXCLUSIVE serialises concurrent index jobs) — TestResolveReferences_FreshRowsResolveInTime
- 2026-10-22 — path.Ext/filepath.Ext('.ts') is ".ts" while Node path.extname('.ts') is '' — files named .ts/.js would be walked in Go but not in Node → guard with domain.IsSupported, not SyntaxForPath alone (walk.json case dotfile_named_like_an_extension)
- 2026-10-22 — decoding clone bytes with []rune(string) or strings.ToValidUTF8: replacement differs from Node Buffer.toString('utf8') (WHATWG: one U+FFFD per maximal subpart, e.g. E2 82 → 1, ED A0 80 → 3) and changes content hashes → use repointel/domain.DecodeText (matched Node on 40k random sequences)
- 2026-10-22 — porting JS float math with Go constants: constant arithmetic is exact (1-0.85, 0.1+0.2 are not rounded like JS) and the compiler may fuse multiply-add → keep such terms in runtime float64 variables with explicit float64() conversions; graphology pagerank parity is bit-exact only that way (repointel/domain/rank/pagerank.go)
- 2026-10-22 — net/http clients that call LLM providers must not follow redirects: Go strips Authorization on a cross-host redirect but keeps custom headers like Anthropic's x-api-key, and resends the POST body on 307/308 (security r1/r2) → copy the client and set CheckRedirect to return http.ErrUseLastResponse (llm adapters, settings/adapters/providers)
- 2026-10-22 — platform/postgres GORM logger without ParameterizedQueries inlines all SQL values into failed (ERROR) and slow (WARN) query lines — a 409 duplicate skill wrote the whole skill body to the log (security r2 N2) → keep ParameterizedQueries: true in postgres.Open (TestSkills_FailedInsertDoesNotLogTheBody)
- 2026-10-22 — ordering names in tests or queries by the default collation: it puts no-then-chains before n-plus-one-gate, while the API (GET /agents, D203) orders by name COLLATE "C" → use COLLATE "C" wherever byte order is expected (seed TestSeed_WritesAgentsSkillsAndLinks failed on exactly this)
- 2026-10-22 — internal/platform/httpx hostName: Go net/http accepts a Host header whose port part is not numeric (Host: localhost:3100.evil.com reached handlers, security r2, live-checked) — cutting at the first ':' turned it into an allowed host → only an empty or 1–5-digit port counts as a match; a non-empty ALLOWED_HOSTS without a valid entry must fail closed, never disable the check
- 2026-10-22 — internal/platform/httpx + transports: reading the request body as JSON regardless of Content-Type let any website send text/plain POST/PUT (no preflight) that overwrote saved secrets — security review r1, confirmed live → read bodies only via httpx.ReadJSONBody (JSON only for application/json; text/plain → 422 "Expected object, received string"), keep the foreign-Origin 403 and ALLOWED_HOSTS guards in httpx.New

## Codebase Patterns
<!-- conventions and architectural decisions not obvious from the code -->
- 2026-10-25 — cmd/server tests of the workspace pruner: the startup prune uses the real time.Now (cmd wires no WithPruneNow, so a moved spec.now can't shift the cutoff) and runs at boot, racing fixture seeding → boot once, wait for its 'trace prune done' line, seed traces aged in whole days, stop, then boot a second stack on the same pgtest DB (spec.db) and assert its startup prune; tests that need exact stats/export use pgtest.Migrated + noSeed with only the default workspace and system user rows (workspace_history_test.go, settings_b_test.go newSBEnv)
- 2026-10-25 — platform/httpx CORS (cors.go) exposes NO response headers, so a download route that sets Content-Disposition must also set Access-Control-Expose-Headers: Content-Disposition (+ Cache-Control: no-store), or the UI on :3100 reads fileName as null (workspace/transport/http export, TestExport_IsADownload) → set both headers in every download handler
- 2026-10-25 — spend/adapters/postgres MonthSpend (FR12): pr_intent, pr_brief and onboarding keep ONE row per PR or repo, so a same-month regenerate replaces the earlier cost (on the real stand an intent refresh costing $0.00375 left the month spend unchanged), and the cap under-counts repeated generations → any exact spend accounting needs a per-call cost ledger or a month rollup (STATUS follow-up, revises D19); don't 'fix' it by summing those tables differently
- 2026-10-25 — cmd/server tests of /settings/spend or the 402 spend_cap_reached: the startup seed (PR #482 demo run, briefs) has cost rows in the REAL current month (spent_usd 0.004547), so any spend/cap assertion changes month to month → use a fixed spec.now far from the seed (spend_cap_test.go capNow 2031-01-15) and assert zero spend first; register such goldens in their own test with that clock (TestContracts_SettingsA)
- 2026-10-23 — cmd/server leaderboard goldens (testdata/contracts/leaderboard_*.json) hold real fixed ids and times, so they bypass the goldens.check placeholder normalizer (it rewrites every …000Z time to 2026-01-01); a new golden there also needs an entry in frontend/src/test/go-backend-contracts.test.ts, or that suite's 'recording for every contract' test fails (a497bfe broke it until S21) → add the frontend contract entry in the same change as the golden
- 2026-10-23 — platform/github Client.GetPullRequest: costs 1 PR request + up to 30 files pages + up to 3 commits pages (TestGetPullRequest_capsFilesAndCommits = 34 requests), so a per-repo request budget (leaderboard NFR3: ≤ 30/repo/cycle) breaks with it → for diff stats only use Client.GetPullStats (one GET /pulls/{n}, same additions/deletions/changed_files), as the background poller does
- 2026-10-23 — internal/tenancy/tenancy.go:48 + internal/seed/seed.go:178: every request resolves its workspace by the fixed name tenancy.DefaultWorkspaceName ('default'), and the startup seed creates a 'default' workspace when none has that name → never let a user-facing rename write workspaces.name; keep the lookup key and store the display name separately (or change both lookup and seed), or after the next restart all requests land in a new empty workspace (Slice B spec G1)
- 2026-10-23 — pulls/adapters/postgres UpsertListed: only the columns named in the ON CONFLICT DoUpdates list are refreshed on existing PRs — a pullRow field outside it is written on insert only, which is how GitHub merged_at stayed missing → add new synced PR columns to DoUpdates and test insert + update (TestUpsertListed_writesMergeStateOnInsertAndUpdate)
- 2026-10-23 — migrations + platform/postgres/migrate/migrate_test.go: the Node-parity tests (TestUp_MatchesNodeSchema, Down→Up, Status, applied-version log) assumed migrations.FS holds only 0001 and broke once 0002_pr_merge_state was added → run them on baselineFS(t) (fstest.MapFS with 0001 only) and count versions via len(Load(migrations.FS)); every other package's pgtest DB gets the full schema
- 2026-10-23 — CI runner (cmd/devdigest-runner) output lands in the GitHub job log, which parses '::cmd::' / '##[cmd]' lines: model and repo text is printed between '::stop-commands::<random token>' and the matching resume line (commandSafeWriter), and FAILED lines are capped (MaxFailureBytes). CI ingest skips runs whose head repository differs from the base repo (fork PR could forge the artifact) — WARN 'ci refresh: run not inspected' reason=head_repository_differs.
- 2026-10-23 — postgres pool is capped (DB_MAX_OPEN_CONNS, default 20; Postgres has 100): inside an InTx body every store call must take its handle via postgres.Conn(ctx, db) — a store using its own s.db while a tx holds a connection deadlocks once the pool is saturated. Cheap audit: set DefaultMaxOpenConns to 1 and run the integration suites; only the deliberate two-connection freeze tests (tx on one conn, observer on another) may hang.
- 2026-10-23 — linking skills to an agent bumps agents.version (a fresh agent with skills is version 2, so its first CI export has manifest_version 2), and PUT /agents/:id accepts a partial body → tests read the version from the DB instead of assuming 1 (phase6_ci_test.go, phase6_evals_test.go)
- 2026-10-23 — freezing concurrent writers of one unique key in a test: with INSERT … ON CONFLICT DO NOTHING the second writer waits on the first's xid, visible in pg_locks as locktype='transactionid' AND NOT granted (not 'advisory') → poll that to know it is blocked without sleeping (ci/adapters/postgres store_test.go TestRecordRun_ConcurrentRefreshes)
- 2026-10-23 — jsonb columns: encoding/json writes U+0000 as the escape \u0000, which jsonb rejects (22P05) even though the text is valid JSON → rewrite that escape to U+FFFD after marshalling, scanning escape pairs so an escaped backslash + u0000 is left alone (evals/adapters/postgres rows.go marshal)
- 2026-10-23 — internal/llm New: Options.Prices == nil does not mean 'no prices' — it starts a live-fed PriceBook (own goroutine + HTTP model listing) → a process that must not price or call out (the CI runner) passes a non-nil Pricer that returns nil (cmd/devdigest-runner noPrices)

- 2026-10-22 — cmd/server test newConfig leaves RepoIntelEnabled false (zero value) while production defaults it on → tests of the ranker / flag-on behaviour set it explicitly (phase3_test.go intelOn)
- 2026-10-22 — freezing a transaction mid-flight in an integration test: an AFTER INSERT … FOR EACH STATEMENT trigger calling pg_advisory_xact_lock(hashtextextended(key,0)) while the test holds the key on another connection; detect 'blocked' by polling pg_locks (locktype='advisory' AND NOT granted) — repointel/integration helpers_test.go (AC3040/3041/3056/3071)

## Tool & Library Notes
<!-- dependency quirks, versions, flags -->
- 2026-10-25 — Postgres SET LOCAL lock_timeout also bounds pg_advisory_xact_lock waits, so two jobs sharing one advisory lock need different timeouts (workspace reset 10 s vs trace prune 60 s, longer than a reset can take) or the shorter one fails with SQLSTATE 55P03; a test of 'held past 10 s' must hold the advisory lock from a separate transaction, because a reset frozen by a trigger is itself cut at its own 10 s (history_test.go TestPruneTraces_WaitsOutALockHeldPastTheResetTimeout, which failed with 55P03 when the prune timeout was set back to 10 s) → give each lock holder a timeout above the others' worst case
- 2026-10-25 — Postgres locks for an atomic 'no running runs, then delete' (workspace reset): LOCK TABLE agent_runs, eval_suite_runs IN SHARE ROW EXCLUSIVE MODE blocks new run INSERTs (ROW EXCLUSIVE) but not FK-check readers (ROW SHARE), so a run that starts during reset waits and survives whole; take pg_advisory_xact_lock first and SET LOCAL lock_timeout so it can't hang (history_test.go TestReset_RunStartedDuringResetIsKeptWhole, TestReset_WaitsForUncommittedRunThenRefuses) → reuse this order for any check-then-delete across run tables
- 2026-10-25 — Postgres 16 pg_input_is_valid(text,'timestamptz') accepts digit-only strings such as '20261015' (a JSON number cast to text), so a guard on an untrusted jsonb time also needs jsonb_typeof(..)='string', and the cast must sit inside CASE, not in a WHERE conjunction, or evaluation order isn't guaranteed (spend/adapters/postgres MonthSpend; TestMonthSpend_malformedJSONDocsSkipped counted 100480000 instead of 480000 before the fix) → guard jsonb casts with typeof + pg_input_is_valid inside CASE
- 2026-10-23 — GORM slow-SQL trace time includes scanning the rows into Go structs: leaderboard qWindowFindings showed 3.6 s in the trace but 0.36 s in EXPLAIN ANALYZE at ~104k rows (AC12, NFR1 volume) → for large result sets measure scan + encode, and aggregate in SQL instead of shipping O(findings) rows to Go
- 2026-10-23 — platform/github StatusError: RateLimited() is only x-ratelimit-remaining == "0" — GitHub's secondary rate limit answers 403 (or 429) with remaining > 0 plus Retry-After or a 'secondary rate limit' message, so code that must back off uses LimitReached() and RetryAfter (pulls poller); RateLimited() is kept unchanged for ci
- 2026-10-23 — gopkg.in/yaml.v3 refuses a '%YAML 1.2' directive ('found incompatible YAML document') that Node yaml accepts, and accepts '%YAML 1.1' where Node changes key resolution; it also has no CR-only line breaks → manifest/workflow parsing fails closed on 1.2 directives; deviations listed in parity/testdata/handwritten/*_deviations.json
- 2026-10-23 — testing/synctest: synctest.Wait() does not advance the fake clock (goroutines in time.Sleep count as durably blocked) → call time.Sleep(d) inside the bubble before Wait() to move time; Go net/http servers strip trailing whitespace from header values, so 'Authorization: Bearer ' arrives as 'Bearer' (evals executor_test.go, devdigest-runner parity_test.go)
- 2026-10-23 — Zod object .refine() runs on a 'dirty' object (too_small/too_big/int issues) but not on an 'aborted' one (wrong type, enum, Required) — e.g. start_line:0,end_line:-1 yields 3 issues incl. the custom one, severity:'HIGH' + end<start yields only the enum issue → mirror that in Go validators for parity (evals/transport/http, goldens/evals.json validation)
- 2026-10-23 — JS-parity text: TextDecoder('utf-8',{fatal:true}) strips a leading BOM (Go json.Unmarshal rejects it → TrimPrefix first); JS /^…/m treats lone CR, U+2028, U+2029 as line starts while RE2 (?m)^ knows only \n → hand-written line scans (ci/domain artifact.go, evals/domain caseinput.go hasFileHeader)
- 2026-10-23 — gopkg.in/yaml.v3 Decoder.Decode(&yaml.Node) has no duplicate-key check and no alias budget, and treats U+0085/U+2028/U+2029 as line breaks and ends anchor names at ':' (Node yaml 2.9 does neither; its alias budget is count*aliasCount > 100, so the 100th alias of one scalar fails) → walk the Node tree yourself with both checks plus a visit budget (ci/domain/wfrules load.go; goldens/wfrules.json)
- 2026-10-23 — go list -deps under CGO_ENABLED=0 silently drops cgo packages (tree-sitter) from the closure, so an import-closure test passes falsely → list with CGO_ENABLED=1 and inspect CgoFiles of non-standard packages (cmd/devdigest-runner closure_test.go)
- 2026-10-23 — JS-parity numbers/dates: strconv rounds exact ties to even but JS toFixed rounds away from zero (0.125→'0.13') → reviewer/domain.ToFixed (big.Rat); V8 Date.parse accepts a lower-case 'z' and Feb 30 (rolls over) and zod datetime() errors do not stop superRefine → see performance/domain/period.go, blast/domain/history.go
- 2026-10-23 — echo/v5@5.4.0 graceful shutdown (http.Server.Shutdown) never cancels in-flight request contexts — a long generation outlives the 20 s grace and Start reports DeadlineExceeded → generations run on the request ctx plus a service stop (platform/inflight Flights/Markers) that cmd calls before stopping Echo (inflight/shutdown_test.go real-listener proof)
- 2026-10-22 — JS-parity text: x/text collate.New(language.English) equals Node localeCompare(b,'en') (0 mismatches / 20k pairs; Collator not goroutine-safe → one per sort); JS String.trim trims U+FEFF but not U+0085, strings.TrimSpace does the reverse → use reviewer/domain.JSTrim
- 2026-10-22 — echo/v5 AutoHandleHEAD runs the GET handler for HEAD, so an SSE route opens a stream on HEAD → answer HEAD explicitly before subscribing (TestEvents_HeadAnswersHeadersAndReleasesTheSubscription)
- 2026-10-22 — Go encoding/json escapes U+2028/U+2029 even with SetEscapeHTML(false), JSON.stringify never does → SSE data lines un-escape them pairwise (reviews/transport/http sse.go unescapeLineSeparators; golden line_separators_are_not_escaped_by_node)
- 2026-10-22 — echo/v5@5.4.0 + Go 1.27 net/http: the hard-coded 30 s ReadTimeout does NOT cut a bodyless streaming GET (startBackgroundRead clears the read deadline before the handler runs), but a server WriteTimeout does → never set WriteTimeout; httpx.OpenStream lifts deadlines and sets a 10 s deadline per frame (stream_test.go; AC4023 660 s manual run)
- 2026-10-22 — go-tree-sitter Node.Child(i) and Node.Parent() are O(position)/O(depth×siblings) (Parent searches from the root): a 400 KB file of '(' took ≈27 min to extract with Child(i) loops → iterate with a TreeCursor and tick a ctx guard every ~1,024 nodes (repointel treesitter guard, hostile_test.go)
- 2026-10-22 — go-tree-sitter@v0.25.0 ParseWithOptions leaks its options via pointer.Save with no Unref (≈186 B per parse; reusing one options object doesn't help) ⚠ conflicts with 2026-10-22 entry recommending ProgressCallback → parse with ParseWith(cb, nil) + Parser.SetCancellationFlag on a C.calloc'd word raised by context.AfterFunc, freed after stop()/done (cgo forbids C retaining a Go pointer); SetCancellationFlag is removed in 0.26 (repointel/adapters/treesitter/parser.go withTree, leak_test.go)
- 2026-10-22 — tiktoken-go/tokenizer@v0.7.0 codec.Count treats special-token literals (<|endoftext|>) as ordinary text, equal to js-tiktoken encode(t, [], []) — not Node's TiktokenTokenizer, which falls back to chars/4 → compare against encode(t,[],[]) in goldens (repointel/adapters/tokenizer tests)
- 2026-10-22 — Go regexp (RE2) (?i) folds s with U+017F and k with U+212A (also inside [a-z]), JS /i without u does not → port JS case-insensitive regexes with explicit [sS]-style classes (repointel/domain/facts.go ci(); 120k-case cross-check vs Node)
