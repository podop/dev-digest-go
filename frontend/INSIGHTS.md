## What Doesn't Work
<!-- dead ends and anti-patterns — the most valuable section -->
- 2026-10-15 — 2026-10-15 — src/vendor/ui/nav.ts (lab 07 worktrees): two branches that each add a sidebar item merged WITHOUT a git conflict, yet B's 'CI Runs' landed in SKILLS LAB while A had created the GLOBAL group the spec put it in (verified on the merge of feat/multi-agents into feat/export-to-ci) → after merging parallel branches that touch NAV, read the merged NAV array section by section instead of trusting a clean auto-merge
- 2026-10-01 — src/test/render.tsx renderWithProviders: it always mounts ToastProvider, which renders a role="status" live region, so getByRole('status') in a component test can match the toast region instead of your own notice, and 'renders nothing' checks on container never pass (container is never empty) → scope with within(screen.getByRole('region', {name})) and assert absence with queryByRole on a concrete control (BlastRadiusCard.test.tsx, PriorPrs.test.tsx)
- 2026-09-25 — testing hover-to-child in jsdom: user-event's hover dispatches mouseout with relatedTarget=null, so React fires onMouseLeave on the parent even when the pointer moves into its own child (verified with a probe test) → don't assert 'stays open when hovering the popover' via user.hover; pin the layout fix instead (e.g. toHaveStyle paddingTop)
- 2026-09-23 — running the full client vitest suite in parallel with tsc/biome (or another heavy job): CPU starvation makes unrelated CodeMirror/modal tests hit the 5000ms test timeout (seen: ConfigTab, VersionsTab, ConventionsView — 4 fails, pass alone and on a quiet rerun, clean HEAD green) → run the full suite on its own before calling a failure real
- 2026-09-22 — component tests that assert an optimistic mutation's EFFECT (e.g. Create skill appearing after Accept): mockFetch returns the same GET body every time, so the mutation's onSettled invalidate refetches the ORIGINAL state and the optimistic change is rolled back before the assertion → assert the gated UI on two fixed states (render with the rule pending, unmount, re-render with it accepted), or stub the GET to change between calls

## Codebase Patterns

- 2026-10-15 — src/test/fetch-mock.ts (mockFetch): routes match on the pathname only and the query string is recorded separately on each request → assert query params via api.requests('GET /path')[i].search, not by putting ?x=y in the route key (evals.test.tsx period param)

- 2026-10-01 — src/lib/hooks/project-context.ts (attachment saves): serial optimistic saves use mutation scope {id: owner×repo} so PUTs run one at a time in click order, and onSettled refetches only when isMutating({mutationKey}) <= 1 — otherwise the refetch overwrites a newer queued optimistic list (paused scoped mutations still count as pending)
